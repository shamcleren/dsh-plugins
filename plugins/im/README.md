# IM 工作台

一个插件管理工作台的即时消息渠道，当前内置个人微信 iLink 与企业微信智能机器人。统一设置入口包含平台选择、连接开关、默认工作区、账号配置、连接状态和实际能力；不同账号、平台与会话保持隔离。

```sh
dhp plugin install im
dhp restart
```

进入 **设置 → 插件 → IM 工作台**，选择平台。个人微信点击扫码绑定；企业微信配置机器人凭据引用、允许用户与管理员，再启用接收。新安装默认不连接任何平台。企业微信文档、日程等办公能力仍由独立的 `wecom-tools` 提供。

| 平台 | 配置与使用 | 能力 |
| --- | --- | --- |
| 个人微信 | [扫码、账号、媒体、主动通知](README.wechat.md) | 文本、图片、文件、视频、审批、追问与持久化通知队列 |
| 企业微信 | [机器人凭据、用户权限与多机器人](README.wecom.md) | 单聊与群聊、文本、媒体、审批与追问 |

`/help` 查看命令；`/workspace` 查询或选择工作区；`/new` 新建会话；`/status` 查看当前会话。帮助与工作区查询无需先创建模型会话，账号权限仍按各渠道配置执行。消息格式、媒体读取、Host 和连接失败使用不同提示，状态页只保留错误分类和时间，不显示消息正文或凭据。

渠道默认工作区使用“平台 · 名称”：例如 `微信 · 生活助手`、`企业微信 · 开发助手`。微信在设置页填写工作区名称（`wechat.workspaceName`）；企微使用当前机器人的名称（`wecom-aibot.name` 或 `bots[].name`）。未命名时，微信显示账号的稳定短标识，企微显示默认机器人或 Bot ID。微信多个账号仍共用其渠道默认工作区，不会为改名拆分会话。

升级时会更新原默认标题，之后只跟随本插件记录的自动标题；手动改名或明确选定的工作区保留。目录、工作区 ID 与历史会话不变，改名不重连账号。标题记录位于 `DSH_HOME/channels/im-workspace-titles/`，只存工作区 ID 和显示名。

## 从旧插件升级

已安装本仓库 `wechat` 或 `wecom-aibot` 时，退出 DSH 后执行 `dhp update`，再重新启动。受保护的更新事务会安装统一发布包、移除旧包并保留账号、凭据引用、工作区设置、消息游标、通知队列和会话绑定；原来未安装或停用的平台不会自动连接。旧配置命名空间 `wechat`、`wecom-aibot` 保留，新连接开关为 `connectionEnabled`，不重新解释旧版已忽略的 `enabled` 字段。

旧安装命令作为 `im` 的安装别名；已有旧包时会走相同的整体更新事务。卸载旧包名只卸载对应旧包，不卸载整个 IM。统一安装后的渠道启停在 IM 设置页操作，卸载整个插件使用 `dhp plugin remove im`。配置及插件数据不随卸载清除。

## 扩展平台

飞书、Telegram 尚未实现。新增平台放在 `src/adapters/<platform>/`，通过公开的 `IMHub.register(adapter)` 注册能力及内存状态，并由适配器拥有连接、账号与关闭流程。公共核心复用 Host 会话、管理命令、状态校验和错误分类；平台认证、消息格式和审批表现仍由适配器实现。扩展在同一包和管理入口发布，不要求用户逐个平台安装工作台插件。现有 `wechat_*` 工具与 `wechatPush` 服务保持兼容；本版本没有宣称跨平台通用的主动发送工具。

架构参考与边界见 [统一 IM 决策](../../docs/decisions/unified-im.md)。本插件只使用锁定的 DSH `0.2.1-rc.5` 公开扩展点。
