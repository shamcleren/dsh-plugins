# GitHub 项目接入与显式保存

GitHub 接入放在独立插件中，复用本机 GitHub CLI 的认证和 Git credential helper。登录、仓库选择与保存策略由插件页面上的用户动作控制，不向模型暴露账号 token，也不修改全局 Git 凭据 helper。专用 GitHub App 授权和跨设备会话恢复留待后续版本。

项目目录属于插件数据根下的受管区域，通过官方 `workspaceRegistry.create(path, title)` 加入原生工作区。相同路径复用稳定身份；删除工作区注册后可重新接入。项目目录与 DSH 会话持久化分开，仓库同步不等于工作台整体备份。

提交与推送是独立动作。预览在临时索引中建立完整树，提交前重建并比较树与 HEAD；提交对象引用已审阅的树。持有原生 index.lock 后，通过比较旧值的 update-ref 更新分支，再安装保留未选中暂存条目的索引。不改工作树文件，审阅后新写入的内容留作后续改动。不可恢复的索引安装失败明确报告已产生本地提交，不自动回滚或重推。

网络同步使用 HTTPS github.com，拒绝改向其他远端或额外 push URL；不运行 hooks、外部 diff 和子模块递归。拉取仅允许干净工作树的快进，推送明确指定用户看到的提交和当前分支，不使用强推。冲突和远端保护交给 Git / GitHub 的既有机制，不自动扩大权限。

认证流、子进程、临时索引和 HTTP 路由都由插件实例持有。卸载停止接收工作、取消账号登录与子进程，等待已拥有任务清理完毕；持久项目与未知锁保留。公开包校验与隔离 Host 验证沿用仓库的发布流程。

0.2 起，仓库按个人、组织与直接协作范围分层分页，避免平铺大量操作按钮。打开仓库作为有生命周期的后台任务执行，HTTP 立即返回任务身份，阶段与对象进度单独轮询；取消信号不依赖原请求是否保持连接，也不冻结其他项目的浏览。活动轮询只读取本地任务与记录，不重复查询 GitHub 账号。

自动同步按项目明确启用，已有数据不自动升级为开启状态。同步固定账号与分支，遵循同一套输入、远端和提交流程校验；现有暂存内容、远端新提交与策略失败会暂停。插件不自动拉取或自行解决分叉。自动提交使用独立索引建立树，并在持有真实索引锁后再次检查暂存区，避免接管其他提交过程。任务与定时器随实例卸载清理，关闭自动同步先取消在途任务再持久化关闭状态。

0.3 起，缺少 GitHub CLI 时由插件异步安装官方固定版本，在下载前约束来源、校验内置摘要后只读取归属已知的可执行文件。安装不依赖系统包管理器，专用 PATH 同时覆盖 API、登录和 Git 凭据 helper；缓存复用前校验，安装锁与共享准备任务归插件所有，卸载等待取消清理。Git 本身与可选 git-crypt / GPG 由本机提供。

git-crypt 设置在单独的本地 JSON 文件中保持唯一来源，页面与手写配置共用；仅保存密钥路径或 GPG 引用。仓库默认检测加密，解锁之前拒绝注册、提交和自动同步。公开 git-crypt 命令完成解锁，固定 clean/smudge 与 required 驱动，拒绝额外的 process 驱动。Git 的保护配置也传给解锁子进程，避免其内部 checkout 执行 hooks。中断恢复只重写与索引完全一致的密文文件，保留明文改动。

加密审查覆盖审阅树与待推送历史，验证密文格式及 git-crypt 认证，当前和历史属性策略取并集，不能通过删除规则、添加假密文头或伪造本地远端跟踪引用绕过。远端基线通过 HTTPS 实时获取；审查有提交数、文件数和字节数上限。普通差异预览禁用任意 textconv，加密正文在本地编辑器审阅。页面变更加密配置先取消同步并关闭该项目自动保存，防止密钥设置切换与推送并发。
