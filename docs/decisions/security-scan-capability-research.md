# 悟空扫描能力补充评估

状态：后续阶段研究，暂不实施。日期：2026-09-10。

当前优先交付已验证的基础扫描初版，范围与首次使用步骤以根 README 的“代码安全审查”为准。本文中的评测适配器、漏洞模式知识库、跨文件分析增强及动态复现均不属于初版交付门槛，不下载或运行 benchmark，不因这些研究推迟初版使用。

目标是增强漏洞发现能力，不复制平台的界面或管理功能。

| 资料 | 可用于本插件 | 不应混淆 |
| --- | --- | --- |
| [VulnGym](https://github.com/Tencent/VulnGym) | 用已标注的入口、危险操作和传播链检验 Agent；按鉴权、隔离、注入等类别构造回归集 | 这是基准数据，不是装上即可扫描任意仓库的引擎。184 是 advisory 数，408 是入口记录；严格评估选择 verify=1。官方评估器只算覆盖/召回，需另测误报。 |
| [A.S.E](https://github.com/Tencent/AICGSecEval) | 借鉴正常功能测试与漏洞触发测试联合验收，检验生成修复是否保持功能且消除漏洞 | 扫描脚本依赖数据集指定的文件、镜像、命令和漏洞类型，不能直接当通用 Python/Go/JS 扫描器。 |
| [InfraScope 论文](https://arxiv.org/html/2605.20051v1) | 从已知漏洞提炼触发条件，在目标模块中检索同类路径，再独立验证候选；保留检查历史和否决理由 | 属于参考漏洞驱动的变体发现，论文结果不能直接当作本插件或悟空平台的效果保证；此次未确认可安装的公开引擎包。 |

建议增加三项能力：带出处的漏洞模式知识库；入口到危险操作的跨文件证据链与独立反证检查；固定仓库版本上的真实漏洞/修复版本评估。优先针对 Python、Go、JS 中的鉴权缺失、租户隔离、SSRF、路径访问、注入和反序列化。现有规则与受限 Agentic AI 保留，新的模式用来引导主动发现，不将候选自动升级为已确认。

评估集与检索知识库分离，避免把标准答案提供给被测 Agent。记录逐语言/漏洞类型的召回、误报、耗时与 token，修复版本作为反例；只证明合成样例接线通过不足以证明真实扫描质量。

动态验证需要单独的受限运行环境和生命周期；当前插件仍不执行扫描目标或 PoC。A.S.E 的部分配置允许 privileged 容器，不能原样纳入默认安装或 DSH 编辑 hook。若后续实现，应使用固定镜像摘要、隔离副本、资源预算、默认断网与显式触发。

平台界面显示 Python/Go/JS、Git/源码包等选项，但本次未提交远端任务、上传代码或验证其检测效果。正式 API 和结果导出契约尚未确认；企业使用指引被浏览器策略拦截，未读取，亦未绕过。
