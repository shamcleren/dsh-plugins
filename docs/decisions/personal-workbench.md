# 个人工作台的交付与场景边界

工作台围绕官方 DSH 的 Session、工作区、工具、审批和原生调度组织能力。桌面负责配置与结果查看，微信提供当前聊天的任务入口和交付通道。插件独立安装与发布，运行时保持独立锁定。

`dhp doctor` 与 `dhp update --check` 是只读诊断入口，检查安装记录、锁与事务、目标 DSH 版本声明、启动文件、凭据文件权限、进程、端口和保留备份。它们不执行账号验证，也不代替更新事务中的完整校验。诊断显示所有可识别的兼容冲突，不自动移除插件。

`docs/modes.json` 是场景组合的权威清单。首批为远程开发、资料简报；`dhp mode list/plan` 展示依赖、准备步骤和任务示例。模型、账号、工作区与工具权限由用户选择。后续自动激活需要先具备公开的配置事务和健康检查路径，失败时必须可恢复；当前清单不宣称已自动激活。

微信 `/tasks` 与 `/cancel` 只针对本账号/对端聊天拥有的活动回合。取消通过官方 Session controller 请求，原生回合结束事件决定最终状态。跨桌面任务的主动通知继续通过已有持久化队列和回执交付；通知额度与互动窗口由渠道约束。

发布使用干净构建。运行源码、Skill、构建配置和 workspace 依赖锁形成 `sourceDigest`，同时写入 catalog 和包内 manifest。发布检查确认当前源码与摘要一致、manifest 合同及打包清单一致、公开导出存在，再执行实际发布包行为和隔离 Host 检查。既有版本不可覆盖。

GitHub Actions 只执行验证，不自动发布、改用户安装或启用外部账号。Linux 验证脚本、插件及隔离 Host，macOS 补充原生构建与应用壳检查；真实微信收发和模型账号验收单独记录。
