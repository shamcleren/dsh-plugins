# SaaS Browser Workspace 0.2.0 实验性验收

日期：2026-11-13。未发布 catalog，未更新用户现有安装，未修改官方 DSH 源码。

## 复用验证

- 在独立官方 DSH 0.2.1-rc.5 Web profile 中实际尝试安装 `@try-works/dsh-browser-agent@0.6.0`。CLI 因其旧版宿主依赖拒绝安装；没有启用豁免。
- `@anweat/dsh-browser@0.2.3` 安装、服务启动与浏览器会话可用；当前复用其公开服务，接管 UI 由本插件补齐。

## 已通过

- 严格类型检查与 client/server 构建。
- 原有状态、查询、登录和导航测试，以及新增原生浏览器控件、配置读取、指定空间路径与非法参数状态测试，共 19 项。
- 原生后端和旧 MCP 后端均使用真实 Chromium 验证 HTTP 登录导航升级为已授权 HTTPS。临时 HTTPS 服务器收到请求，明文请求计数为零；参数保留，未授权来源仍不升级。
- 构建后的真实 tarball 经官方 CLI 安装到新 profile，使用获准的 Grok 路由运行本地测试站点：模型请求关键词表单 → 提交补参并由原生队列续跑 → 查询出 3 条记录 → 选择记录 → 模型打开配置并展示字段。
- 同一 smoke 检查真实模型标识与原生工具事件、JPEG 画面、匿名拒绝、错误会话拒绝，以及配置密码不进入观察结果。
- 真实站点已在 DSH 内弹框显示正常的企业登录页。此前重复的客户端拦截定位为 HTTP/HTTPS 来源不一致，已通过发送前升级修复。
- 企业登录完成后，真实 Grok 在操作者指定的空间执行查询、展示结果，接收界面中的记录选择，打开对应配置页并读取模型设置、记忆参数和关联资源数量。重新读取确认上次保存时间未变，未执行保存、发布或运行。
- 验证了真实空结果：给定关键词在指定空间中不存在时返回空表，没有偷偷切换到服务市场或其他空间。
- 在真实账号页面完成了界面验收：模型生成关键词表单，填写并提交后原生会话自动续跑；表格与列表展示同一批 3 条记录，汇总显示当前已读取 3 条；从表格选择一条后再次打开真实配置页，并在 DSH 弹框内核对原页面连续截图。
- 实际页面使用“去配置调试”文案，已纳入只读入口；没有配置按钮的市场记录仍可提交选择，由模型查找同名记录的开发入口，不自动替换记录身份。
