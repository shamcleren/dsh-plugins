## 实际模型与扫描器

独立临时目录中使用 Semgrep CE `1.176.1` 扫描合成 Python、Go、JS 代码，然后通过官方 `dsh-llm-pi-ai` 和只读凭据解析复用当前 DSH 默认模型 `hy3-ioa`。没有读取业务源码、执行样例、执行漏洞载荷或修改用户配置。

第一次验收发现同一风险在规则候选与 AI 补充中重复计数，以及对未展示路由注册的 Go handler 过度确认。增加同位置/CWE 去重、明确实际入口和保护措施的证据要求后复验：

- 6 次模型调用，读取全部 4 个样例文件，复核 2 项规则候选，补充 1 项规则未检出的 JS XSS；无重复项。
- Python 已注册 Flask 路由将请求输入传入 `eval`：确认，引用路由与危险调用。
- Go 的 `sh -c` handler 没有路由注册证据：保持待复核，明确缺失调用/路由上下文。
- JS HTML 反射：补充 XSS 与输出编码建议。
- 安全 JSON 响应样例：没有告警。
- 两次无效提交被校验拒绝，模型在预算内纠正请求。报告有实际已读行引用和修复建议；没有声称执行测试或利用。
- 适配器返回输入 28,951、输出 5,729 Token。这是本次样例的实际用量，不是成本或所有项目的估算。

这是有界样例验收，不证明 LLM 零误报、完整业务覆盖或安全认证。审查的正式安全要求仍需结合项目威胁模型、人工复核和针对性测试。

## 工作台与发布入口

`0.4.0` tarball 经仓库安装命令安装到临时 profile，真实 Host 使用独立端口。浏览器通过侧边栏进入工作台，创建带 AI 的本地任务；官方 DeepSeek HTTP 适配器连接本机合成模型完成计划、发现文件、读证据、提交、结束的五轮完整工具流程。HTML 预览包含 AI 执行记录、覆盖文件、引用和建议；原始规则报告另行保留。

合成 HTTP 模型只用于稳定验证接线、界面和发布包；上述 `hy3-ioa` 测试另行验证实际模型行为，二者不混同。CLI/Git hooks 继续执行规则，不自动启动 AI。此前全量/增量/暂存区、Git 基线与 hooks 的验证见 [0.2.0](security-scan-0.2.0.md)，独立工作台生命周期验证见 [0.3.0](security-scan-0.3.0.md)。

最终发布包的浏览器验收还覆盖任务复制与独立预算：原任务保留 12 轮，副本设为 3 轮后按预算停止，显示覆盖不完整并保留可查看的部分报告。浏览器下载的 JSON 与保存数据完全一致。
