# Security Scan 0.6.0 验证

日期：2026-09-10；macOS arm64，官方 DSH 0.1.0-rc.8。

## 失败记录诊断

只读检查用户授权的历史扫描：规则与密钥已有结果，最终状态为 partial，AI 第 5 轮因工具请求多次被拒绝而结束；旧记录没有具体拒绝原因，不能事后认定某一参数就是原始原因。另有源码数量/快照上限及不支持的依赖格式，分别属于真实覆盖缺口。

原记录共 532 项候选，其中 16 项属于可取证源码；0.5 将大量依赖公告混入源码复核输入，且要求所有候选具有源码引用，形成不合理的输入和完成条件。0.6 对源码候选分页，保留其他引擎结果及排除计数；工具参数、未读引用和范围错误返回可纠正的安全原因码，记录在 UI/报告中。没有放宽源码引用、路径、工具权限或预算约束。

原业务仓库未被重扫或修改，未新增真实模型调用。文件上限与 uv.lock 支持范围没有改变，报告仍会诚实标明这些缺口。

## 两个启动入口

- 发布包安装到独立 profile，工作台开启“同步到 DSH 会话”，执行真实 Semgrep/Gitleaks 扫描合成 Python/Go/JS 文件，完成并生成 3 项候选及 HTML 报告。通过“打开会话”进入真实 DSH，会话包含阶段和完成通知。
- 在同一隔离 Host 的真实 DSH 对话中发送后台扫描请求。官方 DeepSeek HTTP 适配器连接本地合成模型，返回 security_start_scan 工具调用，正式 ToolRuntime 执行后创建后台任务；第二次模型响应结束对话。该任务以 conversation 标记进入工作台并成功完成，进度回写原会话。
- 从工作台再次启动上述保存任务，生成新的独立 session，归属对应工作区；与会话发起使用的原 session 不同。关闭工作台不停止扫描。
- 会话内容通过公开 ApiProxy 创建/命名，Session.append 与 flush 记录为插件 notice，不伪造模型消息，不执行额外模型审计。合成模型服务共收到两次对话请求，后台规则扫描没有额外模型请求。

最终 Web 启动使用 App 内置 Node 24.19.0 和官方入口。沙箱内启动曾遇到文件监听 EMFILE；以正常进程权限启动同一隔离 Host 后通过，未修改上游或用户实例。结束后仅停止本次拥有的服务，3198 端口和任务锁释放，恢复隔离 profile 的原配置。旧 3196 实例与用户 ~/.dsh 保持原样。

## 检查

- 插件 60 项测试通过，无跳过，含真实 Semgrep、官方 profile loader、候选隔离/分页、参数纠正、会话通知持久化、双入口共享队列、同步关闭和同步失败保留扫描结果。
- TypeScript typecheck、服务端/客户端构建通过；根工程脚本 45 项测试通过。
- 最终 0.6.0 包通过 catalog 身份、大小、摘要与逐文件内容检查，并经正式安装命令安装到隔离 profile。旧版 tarball 保留。

本次验证证明流程接线和回归行为；合成模型测试不等于真实模型在原业务仓库上的重新验收，也不包含 benchmark、动态利用或新增依赖锁格式支持。
