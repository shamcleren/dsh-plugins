# 企微 0.7.2 默认模型修复

2026-10-30。用户在本机配置两个机器人后，两个 Bot 都返回“处理请求时发生错误，请稍后重试。”

## 原因

Schemastery 会把未配置的可选 `model` 对象解析为 `{}`；已有设置也可能保存这个空对象。旧运行时只判断 `model !== undefined`，因此把 `{}` 当作显式模型传给 Session 创建逻辑。后续模型选择找不到 `provider` / `model`，会话创建失败，渠道返回统一错误提示。这个问题同样影响默认模型留空的单机器人配置。

通过 `Config({ bots: [{ id: 'alpha' }, { id: 'beta' }] })` 可直接复现两个空模型。之前隔离测试使用未经配置 schema 解析的对象，漏掉了实际默认值。

## 修复与验证

`0.7.2` 在运行时策略入口把空模型解析为继承 Host 默认；完整模型保持原值，不完整的非空选择在连接前拒绝。保留 schema 的类型与验证，不修改用户 profile 中的空对象，不覆盖全局模型选择。

- 企微类型检查、构建、17 个文件共 94 项测试通过。
- 新回归覆盖单/多 Bot schema 默认值、已保存空对象、独立显式模型、不完整选择拒绝。
- 双 Bot 路由回归从真实 schema 输出构建路由器，分别接收消息并得到最终回复；创建请求不带空模型，两者 Session ID 不同。
- 新 tarball 的 catalog 身份、大小、摘要、导出和兼容约束检查通过。
- 使用 App 内嵌 Node `24.19.0`、官方 DSH `0.2.1-rc.5` 在隔离目录真实安装全部 9 个发布包，完成 Host 启动、动态表单、认证 RPC、安全扫描、离线容错和市场操作 smoke。
- 使用本机当前两 Bot 的配置执行新版本解析，两者均继承默认模型。

通过标准 `dhp stop` / `dhp update` / `dhp start` 更新本机，保留机器人凭据与配置。不代用户向真实企微会话发送消息；修复后的真实账号往返仍由用户重试确认。
