# 统一 IM 0.1.0 验证

基线为 `b287519a3edc6315c5761527235966a6a7357588`，运行时保持官方 DSH `0.2.1-rc.5`。微信与企微协议实现迁入同一个包，保留旧配置命名空间、工具名及账号数据路径；共用会话、命令、错误分类和管理入口。没有修改官方模块。

| 检查 | 本机结果 |
| --- | --- |
| 全部组件严格类型检查及发布构建 | 通过 |
| 根脚本及全部组件测试 | 727 项通过，3 项可选工具测试跳过；IM 202 项全部通过 |
| macOS 原生应用测试 | 25 项通过；首次沙盒执行因 LaunchServices 限制失败，沙盒外复验通过 |
| 8 个 catalog 发布包 | 身份、运行时、大小、SHA-256、源码摘要及公开资源检查通过 |
| 官方 Host 真实启动 | 通过；统一包内两个适配器、原有微信工具及工作台能力正常注册 |
| 管理接口鉴权 | 已认证请求通过，匿名与外域请求被拒绝 |
| 旧版发布包整体更新 | 微信 0.7.1、企微 0.7.5 替换为 IM 0.1.0，重复更新无操作 |
| 配置迁移组合 | 旧预设迁移与 IM 迁移同时执行，平台启停、配置、凭据引用及测试数据保留 |
| 实际插件管理页 | Chromium 与 Safari 均通过；中英文、深浅主题、1280/760/390px 宽度、禁用及未保存状态检查通过 |

布局测量确认所有受检单行输入框、下拉框及接收开关均为 40px；桌面首行三个控件顶边一致，窄窗口自动分栏，没有页面横向溢出。实际页面验证了工作区保存、多机器人名称保存与切换、未保存改动的切换保护，以及无凭据时的平台启停。最终截图取自 catalog 发布包的隔离安装。

回归覆盖空 `client_id` 回退至精确消息 ID，以及模型会话创建失败时的 `/help`、`/workspace` 和未知命令。会话创建以 Host 返回身份为准；已有会话不重复创建。企微 schema 保留“未填写机器人列表”与“明确清空列表”的区别，首次表单可编辑。

所有账号与数据均为隔离夹具，未登录或使用真实微信、企微账号，也未进行手机端消息收发验收；对线上报错的修复依据是已复现的代码路径，不能据此断言唯一线上根因。飞书与 Telegram 尚未实现，后续通过同包适配器扩展。

根依赖锁变化会影响每个组件的发布摘要，因此同时准备了其余已发布组件的新版本；这些包的功能范围不因 IM 合并而扩张。
