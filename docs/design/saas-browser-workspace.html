DESIGN PROPOSAL · 2026-11-12

让 SaaS 成为 DSH 的可操作工作台

在原会话里提出任务，在旁边查看原页面与业务视图，补充输入后继续执行。优先组合现成浏览器插件与生成式 UI 组件，只补齐任务、数据来源和动作控制之间的连接。

基线 DSH 0.2.1-rc.5设计背景 · 最小 demo 已实现单网站 / 单账号 / 单任务不修改官方源码
设计结论现有插件调研交互示意公开扩展点完整流程数据与动作协议第一版范围验收与风险证据索引
设计演进（2026-11-13）：下文保留首轮方案与调研背景。当前 demo 已切换为真实模型，通过三个工作台工具逐步观察、查询和查看配置；复用社区浏览器服务，并在 DSH 弹框内提供实时页面与接管。旧固定配方的验证结论不能替代新流程验收。插件 README 是当前实现范围、复用结果、启动方法与限制的权威说明。

01 · 推荐方案

可以实现截图 + 表单 + 仪表盘 + 表格 + 信息列表，而且不需要重做 DSH 会话系统。右侧采用官方 session 标签页；浏览器底层优先验证官方 Playwright MCP provider；业务 UI 优先验证 @changfenhuang/dsh-genui/embed 的受限组件子集。

建议插件暂名 SaaS Browser Workspace。它在 AI OS 中承担“执行通道 + 任务交互面”的角色。DSH 主 Agent 继续负责理解、规划和调用工具；领域知识、业务规则和完成标准仍由任务约定或领域 Skill 提供。

第一版要证明什么

用户在会话中要求查询网站资料；插件采集可验证数据，在同一个 session 旁显示筛选表单、表格、列表和简单汇总，并能回看对应截图。

这些视图由任务和数据动态选择、组合，不要求模型生成可执行前端代码。

选型结论的证据级别

已核对：本地锁定包的 exports、类型和实现；官方浏览器 provider 的同版本发布包；社区候选的文档及部分接口；目标站点登录后的列表结构与一次关键词查询。

验收边界：打包后的官方 Web profile 已通过本地站点查询、补参续跑和截图检查。已补充一个真实站点的登录续跑与查询验证；macOS 应用壳仍需单独验收，本地假数据不能代替真实账号验证。

用户已明确授权只读查看开发站点。已通过现有 Chrome 登录会话进入“服务市场 → 智能体”，核对卡片字段并完成一次关键词查询，第一条任务据此确定。勘察未创建、修改或执行业务资源；独立浏览器的登录续跑与关键词查询已完成一次验证，其他 SSO 分支未验证。真实地址、账号、记录内容与站点截图不写入公共仓库。

04 · 公开扩展点：哪些可以复用

下表的宿主能力来自 0.2.1-rc.5 的包导出、类型声明及已发布实现，未以最新 master 替代锁定版本。证据路径见文末。

能力公开接口可复用 / 需补齐
模型循环、对话历史原生 Agent / Session / 工具执行链直接复用。不另起一个自行调用模型的任务循环。
工具注册与拦截defineTool、ctx.tools.register、tools/pre-execute、tools/result、ctx.tools.guard复用。本站点规则、动作分类、证据采集由插件实现；guard 只能追加拒绝，不能强制放行其他策略拒绝的调用。
操作审批PreToolDecision.kind = 'ask'、ctx.approval.request，原生 approval UI复用审批界面和结果。具体业务后果及一次性审批绑定仍由插件负责；缺少审批通道时拒绝。
简单问题ctx.userQuestions.ask / askTimed / answer复用选择题/文字输入。其问题类型并不是任意表单 schema；日期、数值、多字段校验由业务面板补齐。
右侧 session 面板ctx.sidebarRightTabs.register → sidebar.right.pane.tab；ctx.sidebarRight.openTab直接复用两阶段注册。通过 slot 注入的 sessionId 绑定状态；不覆盖 root、rightbar.session 等单占位。
会话工具卡片tool.call.toolview，按工具名 keyed 注册；presentCall / presentResult复用外壳，新增任务摘要/打开面板入口。自动审批拒绝仍显示宿主原生拒绝信息。
前后端通信connection.rpc.handle / call；connection.fetch.register复用已鉴权连接与资源路由。新增状态读取、提交表单、取消、截图读取等端点；校验 peer、run 归属和 revision。
回到原会话sessionController.prompt({sessionId, requestId, mode:'queue', content})；工具 exec.concludeTurn()可让等待输入的回合结束，再排队进入同一 session。持久化任务状态、表单 CAS 和恢复收据需新增；不是恢复原 JS 调用栈。
凭据引用dsh-credentials 的 resolve / record 接口可用于未来凭据方案。第一版只在受控浏览器手动登录，不自动导出 cookie、保存密码或收集 OTP。
浏览器生命周期官方 SessionResources / mountSessionMcp 与 provider复用 provider 的隔离、串行调用和卸载清理。ctx.browserUse 仅是 provider 注册服务，没有公开的 Page 对象或通用 execute 方法。
浏览器标签页dsh-client-ui-sidebar-browser：Web iframe；特定桌面环境可用 browser bridge可参考展示方式，不能当作 Playwright 会话。当前 macOS WKWebView 壳也没有实现该 Electron bridge；不假定它能读取跨域 DOM。
截图与结构化数据现成 browser provider 的工具结果，或替代插件的 observe / screenshot 动作浏览器采集可复用；结果解析、遮罩/敏感页面策略、证据存储和来源关联需补齐。首个验收点核对实际截图结果格式。
发布和安装已有 bundle patch、client manifest、catalog 工件和版本检查沿用仓库交付流程。新增插件独立构建、测试、发布；本设计不修改运行时锁和用户安装。

05 · 最小架构与所有权

DSH 原会话→任务与站点策略→浏览器 Provider→页面观察 / 截图→标准数据 + PanelSpec→右侧业务面板
层责任第一版选择
DSH Host模型调用、session、工具生命周期、权限决策、客户端连接全部复用。
Browser Adapter把选定 provider 的工具结果标准化，保留页面状态和证据来源一个 provider、一种适配器。官方 MCP 工具通过 ctx.tools.execute 调用或原生 Agent 调用；不直接调用 ToolDefinition.execute。
Site Profile起始地址、业务/登录来源、页面与控件规则、字段映射、允许的查询动作、完成断言一个人工核对的本地配置；不是扫描整站自动生成适配器。
Run Store / Input Brokersession、站点、账号、运行状态、输入请求、revision、恢复收据插件私有目录中的小型持久化状态；原子写入并串行更新；单活任务。
Observation / Dataset / Evidence有限页面快照、标准行数据、字段来源、截图时间与覆盖范围插件拥有存储；截图不塞入每轮文本上下文。模型读取必要摘要和目标区域。
Surface Client会话卡片、session 标签页、组件渲染、表单校验、来源查看优先 GenUI embed 的白名单组件；原页面预览用普通图片组件。

避免重复拥有资源：官方 provider 拥有 MCP 子进程和浏览器生命周期；本插件拥有 task lease、截图副本、面板与输入请求。关闭标签页不释放用户 session；取消任务只取消本插件工作；卸载停止接收新任务，撤销监听并等待自己的工作结束。

上下文预算：不为每个 SaaS 常驻一套工具。站点目录只返回名称和用途，打开后按需读取当前配置；页面观察限制区域、行数和字节。官方 provider 会公开一组 MCP 工具，应仅保留 demo 必需子集并按已注册工具应用限制；不把它描述成天然只有两个工具。社区 indexed 工具模式可作为后续参考。

06 · 完整交互流程

  1. 准备与启用：在隔离验收 profile 中装载插件和固定版本 provider。检查浏览器可用性与 UI 服务。provider 需要在 Agent 创建/恢复前挂载；不假设给正在运行的 Agent 热插入后就立即可用。
  2. 用户发起：在普通 DSH 会话输入查询目标。任务记录绑定实际 exec.agent.session.id，分配 runId，显示任务卡和右侧面板。第一版同一时刻只接纳一个浏览器任务。
  3. 登录：以 launch 模式打开独立可见浏览器。需要登录时标记 awaiting_login，停止采集敏感页面，用户在浏览器完成 SSO。点击工作台“我已登录，继续”后重新观察业务页面及账号标识。不能只凭按钮点击认定登录成功。
  4. 确定查询条件：能从对话确定的参数直接使用。缺失参数生成表单，保存 inputRequestId 与 revision，返回 awaiting_input 并结束本回合。用户无需回到原网站填写业务筛选条件。
  5. 提交输入：Client 提交已校验字段 → Host 复验 session/run/账号/请求状态/revision → 原子登记一次输入 → 使用固定 requestId 向原 session 排队一条后续消息。重复点击返回同一收据；已失效的表单不可操作。
  6. 观察与执行：Agent 读取新的任务状态，定位服务市场智能体列表，填写关键词并确认查询。第一版只采集当前已渲染结果，不自动翻页或进入独立详情。每次动作使用最近一次观察的引用；输入后重新核对控件，等待查询条件生效和结果更新，不能采集过渡期旧数据。登录失效或页面结构变化时暂停。
  7. 采集与展示：从实际页面提取结构化行数据和截图；对同一 observation 保存来源。模型选择四类组件的布局与字段；后端生成计数和分组，客户端显示并允许查看原页面。
  8. 继续交互：表格排序、折叠、切换列表在本地完成；新筛选或重新查询产生受控任务事件，再进入原会话。用户接管浏览器前，先停止接受 Agent 动作、等待当前操作稳定；交回后重新观察。
  9. 完成：验证所请求条件、读取范围与结果一致，生成 succeeded 或 partial，会话给摘要，面板保留数据和证据。已确认加载完成的空列表是有效结果；无法确认完整性或发生截断时，不报告“全部匹配结果”。
  10. 取消或重启：取消撤销输入请求并中止本任务，不能误停其他用户回合；重启后任务标记 interrupted。展示保存的结果，用户显式继续后重新登录/观察，不自动重放浏览器动作。
created → awaiting_login → observing → awaiting_input → queued → running → verifying
                                                        ↑          ↓              ↓
                                                        └─ needs_human     succeeded / partial
任意活动态 → cancelling → cancelled
进程中断 → interrupted → 用户继续 → 重新观察
后续写入版本：提交结果不明 → outcome_unknown → 查询核实，不自动重试

原生问答与自定义表单的边界：一般选择问题使用 DSH userQuestions。复杂表单使用上述 Input Broker；表单提交后是“原 session 的下一回合”，不宣称 DSH 原生提供了完整、跨进程的业务工作流恢复。

07 · 动态 UI 的数据与动作协议

增加一个小型 PanelSpec v1 作为稳定业务边界，再转换成选定 renderer 的 spec。它可以按任务动态组合组件，但字段值必须来自观察结果或明确标注的用户输入，不能把模型自由生成的数字当作网站事实。

对象必要字段 / 约束
RunrunId, sessionId, siteId, accountRef, status, revision；身份由 Host 绑定，模型传入的 sessionId 不可信。
ObservationobservationId, runId, documentRevision, sanitizedUrl, title, capturedAt, coverage；DOM、数据集、截图引用归于同一轮采集。页面持续变化时注明非原子快照。
DatasetdatasetId, observationId, fields, rows, sourceRefs, truncated, coverage；保留原始类型、单位与空值，不把空值变成 0。
PanelSpecschemaVersion, viewId, runId, revision, blocks[]；不允许 script、HTML、远端 import、自定义 CSS 或任意 URL 请求。
InputRequestinputRequestId, runId, revision, fields, constraints, status；第一版仅业务字段，不接受密码/令牌/支付资料。
ActionHost 预先登记 actionId 及参数 schema、效果类别、目标观察版本。模型不能凭 UI JSON 声明一个可执行接口。

模型工具与 UI RPC

较完整方案原拟拆分为三个工具（最小 demo 已收敛为一个业务工具，见上方实现说明）：saas_task_open（选站点并绑定任务）、saas_request_input（登记表单并结束等待回合）、saas_present（提交数据引用和视图结构）。浏览器动作经过同一套策略，原始 provider 工具也受限制，不能从另一个入口绕过。

UI RPC 拟定为 state / submitInput / resume / cancel / requestRefresh。其中 submitInput 携带 inputRequestId + expectedRevision + submissionId，Host 串行 CAS 并保存稳定的 session prompt requestId。宿主有重复请求识别，插件仍负责并发去重和不确定收据核对。

GenUI 的 GenuiActionContext 只提供交互事件入口。我们将 action 限定为已有 actionId，拒绝未知参数和过期 revision；不能把自由 action 字符串直接转换成浏览器脚本或 HTTP 请求。

08 · 需要补齐的可靠性边界

页面内容是输入数据

网页文字、隐藏字段、网络响应和 UI schema 都不能增加权限。模型不能通过“网页提示”放宽站点策略。数据提取使用有限 DOM/可访问性观察；不把整站 HTML/JS 填入上下文。

浏览器权限独立约束

DSH 文件沙箱不自动限制网页网络或登录账号权限。工具 URL 检查、provider 的域名选项都不等于完整出站隔离；重定向、iframe、子资源和 WebSocket 仍需单独核验。

登录与截图

第一版使用独立可见浏览器，凭据不进聊天、任务日志和截图。登录状态留在 provider 的临时会话中；进程结束后重新登录，不宣称持久登录或自动续期。

“只读查询”由业务语义定义

输入框可能自动保存，GET 也可能触发业务变化。第一版仅开放已核对的列表导航、关键词输入与查询确认；其他网站控件不在动作集合内。不能用 HTTP 方法或按钮名称自动证明无副作用。

对真实站点的前置条件：确认页面跳转及资源加载符合环境访问策略、使用账号允许读取的数据范围、传给模型的数据可见范围。若所选 provider 的公开配置无法提供必要的网络边界，保留这一限制，使用允许的隔离网络环境或替换适配器；不修改官方包或用提示词冒充强制隔离。

后续写入：填写参数和批准提交是两件事。写入前显示目标账号、对象、字段差异及后果；审批绑定本次参数摘要和页面版本。超时后的未知结果先读取确认，不能自动重试或改走 API 重复提交。第一版不提供网站写入动作。

授权勘察得到的页面依据

实际观察对第一版的影响
现有 Chrome 登录会话能进入服务市场的智能体卡片列表，并完成关键词查询。业务任务已确定；尚未验证独立 launch 浏览器的登录，也未通过拟选 DSH provider 执行。
卡片提供名称、类型、版本、标签与描述。一次查询同时命中名称或描述包含关键词的记录。采用这五个业务字段；关键词沿用网站搜索语义，不限定为名称精确匹配。状态、创建时间、更新人等未采集字段不填造。
主搜索是自定义可编辑元素；输入后用于表示空输入状态的 CSS 类会变化。不硬编码状态类或复用旧观察引用。动作前检查唯一定位，输入后重新观察，再确认查询；失配时重新定位，不盲目重试。
导航后曾先显示空列表，稍后加载卡片；确认查询后也曾短暂保留旧结果。加载完成判断属于 Site Profile 的必需合同。条件已提交不等于结果已更新；尚不能证明空结果完成时，保持等待或返回不确定。
关键词查询改变卡片结果，但顶部“全部”及侧栏标签计数仍保留原口径。仪表盘仅由本次采集行生成 count/groupCount；页面全局计数不能充当筛选结果总量。
本轮查询结果可直接从渲染卡片读取；点击所查卡片标题未观察到详情导航，未验证分页。第一版仅当前渲染结果、最多 50 条；“详情”只展开已采集字段。网站翻页、独立详情、标签筛选和排序操作后置。

这里仅记录可公开的交互结构。真实搜索词、数量与运行地址留在本地勘察记录，不能作为固定测试期望。站点会变化，实施时仍需按锁定 provider 重新观察并确认完成信号。

泛化能力怎么验证

浏览器动作、任务协议和四类 UI 可泛化；站点业务语义、登录机制、复杂控件和完成断言仍需适配。第一版交付时，至少验证不同查询词、真实空结果、延迟加载、超过读取上限和过期表单；数量期望按当次观察核对。第二个站点只增加 Site Profile 即可完成同类任务，才构成“跨站泛化”的证据；一个站点成功不足以证明任意网站可用。
